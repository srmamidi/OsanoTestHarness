for DevOps, Osano admins and Ecom Control Center developers v1.1 Recommendation: pipeline
Listen

What this is

The Osano Test Harness opens each website page in a real browser, once for every consent choice a visitor can make (no choice, accept, reject, each category on its own, and the GPC 'do not sell' signal). It records every tracker, cookie and embedded frame, and checks them against the choice. Run it before and after every Osano change. It produces three reports: before, after, and a one-page before-vs-after comparison with a HIGH / MEDIUM / LOW risk rating.

Recommendation

Run the harness as an Azure DevOps pipeline. Ecom Control Center starts that pipeline and shows the results. Do not run the harness inside the Ecom Control Center web application.

Prerequisites

  • Windows 10/11 or Windows Server 2019+ with internet access to the sites being tested
  • Python 3.12 or 3.13 (py -0p lists installed versions)
  • About 600 MB of disk for the browser
  • Network access to the LLE hosts (VPN if off-site)

One-time setup

  1. Copy or clone the folder, e.g. C:\GitRepos-GraceAlone\OsanoTestHarness.
  2. .\scripts\Invoke-OsanoHarness.ps1 -Action Setup — creates .venv, installs pinned packages and Chromium.
  3. .\scripts\Invoke-OsanoHarness.ps1 -Action Test — must show all tests passing. The tests use the built-in demo site, so nothing leaves the machine.
  4. .\scripts\Invoke-OsanoHarness.ps1 -Action Demo — produces sample reports in docs\reports. Open docs\reports\index.html.
  5. Fill config\profiles\ace-prod.yaml and ace-lle.yaml: Osano customer id and config id (from the osano.js URL), real page URLs, LLE hosts. The tool refuses to run while any REPLACE-ME is left.

Every Osano change

  1. Export the Osano configuration (Osano MCP / REST) and normalise it:
    .venv\Scripts\python.exe -m osano_harness import-config --input raw.json --output config\osano_exports\prod-before.json
  2. .\scripts\Invoke-OsanoHarness.ps1 -Action Run -Profile ace-prod -Label before -OsanoConfig config\osano_exports\prod-before.json
  3. Make and publish the change in Osano. Wait about 5 minutes for Osano's CDN.
  4. Export again, then run with -Label after and the new export.
  5. .\scripts\Invoke-OsanoHarness.ps1 -Action Compare -Profile ace-prod and open the compare report it prints.

What the pipeline does

StageWhat happens
1. BeforeSets up Python + Chromium, self-tests, probes every page × choice, publishes the BEFORE report
2. Make the Osano changePipeline pauses (up to 3 days). The Osano admin makes and publishes the change, then presses Resume
3. After + compareProbes again, compares, publishes the reports. Fails the run when the change introduced a high-risk problem (default gate new-high)
NightlyOne run per night of the pipeline's default property, compared with that property's last nightly run (found by build tag). Catches drift: a tag added to the CMS, an Osano rule edited, a new vendor. For a nightly of the other property, copy the YAML with the other default and create a second pipeline.

Set it up (one time)

  1. Agent. Create agent pool Osano-Harness-Win and register a self-hosted Windows agent on a server inside the network (LLE hosts are internal; Microsoft-hosted agents may be blocked by Akamai). Install Python 3.13 for all users. 2 vCPU / 4 GB RAM is enough.
  2. Repo. Push this folder to an Azure Repos repository (e.g. OsanoTestHarness).
  3. Pipeline. Pipelines → New → Azure Repos Git → Existing YAML → /azure-pipelines.yml.
  4. Permissions. Pipeline settings → allow it to use the agent pool. Restrict who can run it and who can approve the pause step (Osano administrators).
  5. Profiles. Commit the filled ace-prod.yaml / ace-lle.yaml. They hold no secrets.
  6. Optional storage. For Ecom Control Center: create a storage account with container osano-reports, an Azure Resource Manager service connection with Storage Blob Data Contributor, and set pipeline variables publishToStorage=true, storageServiceConnection, storageAccount.

Yes — integrate as the front end

Ecom Control Center gets two features. It does not run browsers itself.

A. Results page (read-only)

  1. The pipeline copies reports to blob container osano-reports (<profile>/compare_*.json summaries and *.html reports).
  2. Ecom Control Center lists */compare_*.json with the Azure Storage SDK (managed identity or service principal with Storage Blob Data Reader). Each summary has risk, verdict (IMPROVED / REGRESSED / MIXED / UNCHANGED / INCOMPLETE), counts, compared_utc, before_finished_utc, after_finished_utc and the scorecard numbers (a number can be null = not judged; show it as such, never as 0).
  3. Show a table: Risk (red / amber / green fill), property, date, fixed / new / still open, link to the report.
  4. Serve a report through a controller action that streams the blob with header Content-Security-Policy: sandbox allow-scripts — reports contain text taken from websites. It is escaped, but the sandbox keeps it from ever touching the Ecom Control Center session.

B. Run button

  1. Ecom Control Center calls the Azure DevOps REST API: POST https://dev.azure.com/{org}/{project}/_apis/pipelines/{pipelineId}/runs?api-version=7.1 with body {"templateParameters": {"profile": "ace-lle", "mode": "before-after"}}.
  2. Authenticate with a service principal / managed identity added to the Azure DevOps organisation, with only queue builds on this one pipeline. If a PAT is unavoidable: scope Build (read & execute), stored in Key Vault, rotated.
  3. Show the run link. Approving the pause step stays in Azure DevOps (it is audited there).
  4. Only Osano administrators see the button (Ecom Control Center role check, server side).

Do not

  • Install Chromium or Python on the Ecom Control Center web servers.
  • Pass a user-typed URL or blob path straight to storage — only names from the listing.
  • Put the Azure DevOps credential in web.config — use Key Vault or managed identity.

Known limits

  • Results reflect the agent's location: Osano chooses the consent model by visitor region. Testing EU behaviour needs an agent or proxy in the EU.
  • Accept-all runs send real hits to analytics and ad platforms (small volume).
  • Timings are single lab samples — trust trends, not single numbers.
  • The vendor catalog (config/vendor_catalog.yaml) decides what each third party really is; keep it in step with Osano.
